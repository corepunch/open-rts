# Metadata ownership: ACTOR_TYPES[] vs mobjinfo[]

## Intended split

| Table | Owner | Fields |
|-------|-------|--------|
| `ACTOR_TYPES[]` in `games/*/g_game.c` | **Gameplay stats** | `traits`, `speed`, `max_hp`, `attack.{range,damage,cooldown_ms}`, `harvest.*`, `sight.*` |
| `mobjinfo[]` in `games/*/info.c` | **State machine** | `spawnstate`, `seestate`, `missilestate`, `deathstate`, animation sprite/frame/tics, `radius`, `height` |

Combat reads `mobj->info->attack.*` which points into **ACTOR_TYPES[]** (set by
`P_ApplyActorTypeDefaults`). The `mobjinfo[].damage` and `.flags` fields are
duplicates — `p_mobj.c` does NOT read them for live combat.

## Known mobjinfo indexing mismatch in Dark Reign

Dark Reign uses native `ACTOR_FG_*` IDs (e.g., `ACTOR_FG_CONSTRUCTION_CREW = 11`)
as `mobj->type_id`. The `mobjinfo[]` array is indexed by `MT_FG_*` sequential
values (0, 1, 2 …), so `mobjinfo[11]` is **MT_FG_MARTYR**, not the construction
crew. This means:

- State machine animation uses the wrong sprites (functional but visually wrong).
- `missilestate` happens to be non-null for Martyr so attack still fires.
- `spawnhealth` from mobjinfo is overridden by `actor_types[].max_hp` so HP is correct.

Do NOT try to fix this by re-indexing `mobjinfo[]` without also updating all
callers. The mismatch is load-bearing until a proper mapping layer is added.

## KKnD is clean

KKnD's `MT_*` enum values start at 0 and match the native type IDs, so
`mobjinfo[type_id]` is always correct.

## Generated vs hand-authored

KKnD `info.h/info.c` is fully generated by `tools/kknd_info_gen.c` and must
round-trip byte-for-byte (`make test-info-gen` checks this for KKnD and 7legion).

Dark Reign `info.c` contains **hand-authored** A_Look/A_Chase/A_Attack actions
and state group numbers that the generator does not produce. Do not regenerate
Dark Reign info files with `make dark-reign-info` and commit the result.
